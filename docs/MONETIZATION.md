# 测评后付费与文档交付（实现思路）

## 用户路径

1. 免费填写测评 → 提交成功  
2. 成功页展示「付费获取《退保操作指南》」→ 跳转你配置的收银台/商品页  
3. 用户支付成功后，由支付渠道或你的服务端**发放下载**（PDF/压缩包链接、邮件附件、网盘口令等）

## 常见对接方式

| 方式 | 适用 | 交付文档 |
|------|------|----------|
| **Stripe Payment Link / Lemon Squeezy / Gumroad** | 海外或支持国际卡 | 支付成功页下载链接、或邮件自动发货 |
| **微信/支付宝商户 + 自有 H5** | 国内主流 | 支付结果回调后跳转「下载页」或发短信/邮件 |
| **知识付费 SaaS**（小鹅通、有赞等） | 快速上线 | 商品绑定文件下载，少开发 |
| **Apple IAP** | 仅 App Store 上架的 App | 用「非消耗型」解锁应用内 PDF；需遵守苹果审核规则 |

## 技术要点

- **不要在纯前端「藏」下载直链**：未付费用户可猜 URL。应用层应：**支付成功回调（Webhook）→ 服务端校验订单 → 再签发短期有效下载链接或登录态**。  
- **测评与订单关联**：提交成功时可生成 `submissionId` 或把 `submittedAt` 传到付费链接 `ref`（见 `.env.example`），便于客服对账。  
- **合规**：商品描述与文档免责声明需与法务确认；避免承诺「必退」「包过」等表述。

## 本仓库中的配置

- 环境变量 `VITE_PURCHASE_URL`：付费/商品页完整 URL。  
- 可选 `VITE_PURCHASE_APPEND_REF=true`：在 URL 上附加 `ref=` 提交时间戳。
